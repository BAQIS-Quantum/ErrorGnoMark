# 一、研究问题：A System-Level Benchmark for VQE Compilation under Time-Varying Noise

在 VQE 的多轮迭代过程中，量子硬件噪声参数（frequency、T1、T2、gate fidelity 等）是时间相关且非平稳的，而传统编译假设这些参数是常数。

## 1. 问题详述：VQE 的量子线路结构本身并不固定
每一轮 iteration 的：
    参数
    测量分布
    关键门的使用频率
    都在变化

## 2. 传统 VQE 编译的固有困难（不考虑漂移）

（1）电路深度 vs 表达能力
    Ansatz 越深 → 表达能力强
    但深度 ↑ → 噪声指数放大

（2）测量成本极高
    Hamiltonian term 数量大
    不同 Pauli term 需要不同 basis change
    Shot allocation 本身就是优化问题

（3）参数化电路的可重用性
    每一轮参数更新
    但电路结构相同
    传统编译器无法利用“结构不变”这一事实


## 3. 漂移带来的新问题
漂移类型以及对 VQE 的影响

Qubit frequency 漂移 --> 失谐、串扰增强
T1 / T2 漂移-->深电路误差突增
Gate fidelity 漂移-->优化方向被噪声误导
Readout fidelity 漂移-->能量估计系统性偏差

因此VQE 的 cost function 本身被时间相关噪声污染

# 二、 几个重要的问题

## 模块 1：预测什么？
不是泛泛地“预测噪声”，而是对编译有用的量。
可预测目标（建议）
### 短期（next N iterations）
单 qubit / 两 qubit gate fidelity 趋势
Readout error 演化
### 退化风险指标（更有用）
「某 qubit 在未来 K 分钟内不可用的概率」
「某 pair 的 CNOT fidelity 低于阈值的概率」
不是精确预测数值，而是预测“风险”


## 模块 2：AI 模型的输入什么？

可用输入源：时间序列 + 状态感知

1. 长期校准数据

    frequency / T1 / T2 时间序列

    gate error / readout error

2. EGM（ErrorGnoMark）实时数据

    syndrome-like statistics

    lightweight diagnostic circuits

    background benchmarking

3. 上下文信息

    时间（昼夜、负载）

    温度 / 运行模式

    最近是否 re-calibration



### 模块 3：我目前理解的预测结果如何进入编译器？

1. Qubit Mapping（最直接）

2. Ansatz 结构自适应（很有研究价值）

    在这些后期会劣化的 qubit 上减少 entangling gate

    或选择更浅的 ansatz

    或切换 ansatz family（hardware efficient → problem-inspired）

3. Measurement & Shot Allocation（非常实际）
预测：Readout fidelity 在某些 qubit 上下降
对关键 Pauli term 分配更多 shots
调整 measurement grouping
延迟执行高噪声 qubit 的测量


4. Iteration-aware Recompilation（很重要）

    VQE 每 N 轮：

    更新噪声预测

    重新映射 / 重新编译

    不必每轮都编译（成本太高）

5. Cost Function 的“去噪引导”

    用预测的噪声趋势

    对 VQE cost 做 bias correction

    或在 optimizer 中加入 noise-aware regularization
