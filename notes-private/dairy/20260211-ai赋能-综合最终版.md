# 三、当前设计思路与旧版本的区别

我们从 **量子计算视角** 与 **软件工程视角** 两个维度分析。

---

## （一）从量子计算视角

### 1️⃣ Physical 与 System Capacity 的彻底分离

旧版本中，Capability 与 Physical 边界模糊。

现在：

- **Physical 层：** 原生门、噪声、T1/T2、RB 等
- **System Capacity 层：** 结构资源生成能力（纠缠、非定域性、magic、拓扑连接性）

优势：

- 支持跨硬件比较
- 支持拓扑敏感分析
- 为 QEC 扩展预留空间
- 支持 noise → structure → logical 的映射建模

---

### 2️⃣ QEC 架构前置设计

Logical 层现在包含：

- threshold 扫描
- distance scaling
- syndrome 统计
- logical benchmarking

这意味着：

> EGM 不再只是 NISQ Benchmark 工具，而是提前面向 Fault-Tolerant 架构。

好处：

- 可以比较 decoder
- 可以分析逻辑错误传播
- 可以做 logical-to-algorithm 传播研究

---

### 3️⃣ Hybrid Benchmark 抽象成熟

通过：

```
base_variational_experiment.py
```

抽象出完整 Hybrid Loop：

- 量子电路
- 测量
- 经典优化器
- 参数更新
- 反馈循环

并进一步拆分：

- 梯度噪声分析
- barren plateau 检测
- optimizer 敏感性分析
- 表达能力分析

这解决了你曾经最核心的困惑：

> Hybrid 到底是不是独立层？

答案是：

✅ 不是独立层  
✅ 它属于 algorithmic 层的一种结构形态  

---

## （二）从软件工程视角

### 1️⃣ 单向依赖原则

- intelligence 可以依赖 core
- core 不强依赖 intelligence
- compiler 只存在于 execution 层
- domain 独立存在

避免循环依赖。

---

### 2️⃣ 编译器彻底解耦

Compiler 不属于：

- physical
- system_capacity
- logical
- algorithmic

它属于：

> 横向 execution & compilation 基础设施层

这保证：

- 支持 QSteed 接入
- 支持多编译器并行比较
- 支持 compiler 敏感型 benchmark

---

### 3️⃣ Domain 理论层独立

domain 层包含：

- error_budget
- cross_layer_analysis

作用：

- 理论建模
- 跨层映射
- scaling law 抽象

避免：

- 把理论模型塞进 experiments
- 把跨层建模塞进 intelligence

---

# 九、最终反思：针对你曾经的困惑

我们逐条回答你曾经反复思考的问题。

---

## ❓1. Capacity 到底是不是 Physical？

答案：

不是。

Physical 是“硬件本征行为”。

System Capacity 是“结构资源生成能力”。

二者必须分离，否则无法跨硬件比较。

---

## ❓2. 编译器会不会破坏分层？

不会。

前提是：

- 编译器属于 execution 层
- 不嵌入 experiments
- 通过 metadata 记录

这样可以做 compiler 敏感型 benchmark，而不污染逻辑层。

---

## ❓3. QEC 现在做是不是太早？

不是。

架构必须提前预留。

否则未来重构代价巨大。

Logical 层的 threshold 与 syndrome 结构是正确前瞻。

---

## ❓4. Hybrid Benchmark 要不要单独一层？

不要。

它属于 algorithmic。

通过 base_variational_experiment 抽象即可。

---

## ❓5. Intelligence 会不会污染 core？

只要遵守：

> core 不强依赖 intelligence

它就只是插件。

---

## ❓6. Domain 是否真的必要？

是的。

domain 是：

> 理论与跨层映射知识库

否则理论会污染 experiments。

---

# 二、Capability 的最终定位

## 2.1 Physical Layer 本质

```
原生门
  ↓
执行
  ↓
误差估计
```

关注：

- 原生门保真度
- T1 / T2
- 读出误差
- 串扰
- 噪声模型

定义：

> 纯硬件本征性能表征层

---

## 2.2 Capability Layer 本质

```
抽象结构电路
  ↓
编译 / 拓扑映射
  ↓
原生门
  ↓
执行
  ↓
结构资源分析
```

关注：

- Entanglement capacity
- Nonlocality depth
- Magic generation
- Contextuality
- 多体关联结构

定义：

> 系统级量子资源生成能力评估层

Capability：

- 需要编译
- 不涉及编码
- 不依赖具体应用任务
- 独立于 Physical

---

# 三、Compiler 的最终定位

Compiler 的功能：

```
抽象电路
   ↓
编译 / 优化 / 映射
   ↓
硬件可执行电路
```

它：

- 不属于 Physical
- 不属于 Capability
- 不属于 Logical
- 不属于 Algorithmic

它属于：

> 横向 Execution & Compilation 基础设施层

它是跨层转换器，而非评估层。

---

# 四、AI 的最终定位

AI 不属于任何 Evaluation 层，也不属于 Compiler。

AI 属于：

> 横向 Intelligence Infrastructure（智能增强层）

作用：

- 局部 Benchmark 优化
- 跨层数据分析
- 自动检测方案匹配
- 性能预测
- 编译器 / Backend 智能选择
- 异常检测
- 自适应实验规划
