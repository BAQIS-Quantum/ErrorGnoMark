# EGM 开发路线规划（Development Roadmap）

作者：项目负责人  
状态：阶段性规划文件  
适用范围：当前及未来参与 EGM 开发的成员  

---

## 一、文档目的

本文档用于：

- 明确 EGM 接下来阶段的核心开发方向；
- 描述各模块在整体架构中的定位；
- 说明每个模块完成后的“终态样貌”；
- 粗略估算开发所需人力投入；
- 为成员自主认领方向提供参考。

本文件不指定具体负责人。

模块的认领应基于：

- 成员兴趣；
- 技术背景；
- 可投入时间；
- 实习周期。

EGM 的整体架构设计与演进方向保持稳定。  
人员流动不影响系统主轴。

---

## 二、当前阶段总体目标

当前阶段的目标是：

> 完成 EGM v3 system 层稳定化，并建立可扩展能力基础。

整体分为三个层面：

1. system 稳定化阶段  
2. 扩展能力建设阶段  
3. 研究与应用准备阶段  

---

# 三、模块规划

---

## 模块 A：system Version & Event Engine 完整实现

### 1. 架构定位

属于：

Level 0 —— system 语义层

核心工作流中的位置：

Event → apply() → new HardwareState → new Version → Snapshot

这是 EGM 的演化主轴。

---

### 2. 最终完成状态

- Version Graph 完整实现；
- 支持 DAG 分支结构；
- 状态不可变性严格保证；
- Event 应用路径唯一；
- Snapshot 与 Version 绑定稳定；
- 核心路径单元测试充分覆盖；
- 不存在隐式写路径。

完成后，system 抽象进入冻结状态。

---

### 3. 人力成本估算

- 全职投入约 4–6 周；
- 或分布式投入约 2–3 个月。

属于高复杂度、高结构价值模块。

---

## 模块 B：Snapshot 与 Query 接口完善

### 1. 架构定位

system 与上层模块的只读接口层。

为 intelligence、domain、suites 等模块提供统一访问能力。

---

### 2. 最终完成状态

- Snapshot 提供结构化查询接口；
- 支持按 Version 查询；
- 支持指标筛选；
- 支持时间窗口提取；
- 明确标注接口稳定等级；
- API 文档完整。

完成后，上层模块无需直接访问 HardwareState。

---

### 3. 人力成本估算

- 全职投入约 3–5 周；
- 或分布式投入约 2 个月。

属于中等复杂度模块。

---

## 模块 C：时间序列抽取能力（Time-Series Extraction）

### 1. 架构定位

位于 system 上方的扩展能力层。

为 intelligence 模块提供数据基础。

---

### 2. 最终完成状态

- 提供 get_metric_series() 接口；
- 支持时间窗口；
- 支持聚合策略；
- 支持批量提取；
- 输出标准化数据结构；
- 不修改 system 结构。

完成后，预测与分析模块可独立发展。

---

### 3. 人力成本估算

- 全职投入约 3–4 周；
- 或分布式投入约 1–2 个月。

属于扩展型模块。

---

## 模块 D：domain Error Modeling 重构与规范化

### 1. 架构定位

Level 1 —— domain 语义扩展层。

负责将数值分析提升为语义 Event。

---

### 2. 最终完成状态

- error_analysis 与 error_modeling 明确分层；
- domain 只输出 Event；
- 不修改 system 抽象；
- 提供清晰接口文档；
- 测试覆盖语义边界。

完成后，domain 与 system 解耦稳定。

---

### 3. 人力成本估算

- 全职投入约 4–6 周；
- 或分布式投入约 2–3 个月。

属于语义密集型模块。

---

## 模块 E：PredictiveContext 结构设计（研究准备）

### 1. 架构定位

intelligence 扩展层。

不影响 system 结构。

---

### 2. 最终完成状态

- PredictiveContext 数据结构定义；
- 与 Version 绑定但不写入 Version DAG；
- 风险结构标准化；
- 独立于 HardwareState；
- 明确标注为实验接口（L2）。

完成后，可支持 AI–Compiler 研究方向。

---

### 3. 人力成本估算

- 全职投入约 2–3 周；
- 或分布式投入约 1 个月。

属于研究准备模块。

---

# 四、模块认领机制建议

每位成员在认领模块时应提交：

1. 预计可投入时间；
2. 预计完成范围；
3. 预计可交付内容；
4. 阶段性里程碑。

交付定义必须明确：

- 功能完整性；
- 单元测试覆盖；
- 文档说明；
- 不违反 system 设计原则。

---

# 五、长期稳定性声明

EGM 的 system 设计原则与架构方向保持稳定。

人员变动不影响：

- Version 模型；
- Event 机制；
- Snapshot 结构；
- system 不变量。

任何模块必须具备可持续演进能力。

---

# 六、阶段性优先级

当前优先级排序为：

1. system 稳定化；
2. Snapshot 与查询接口完善；
3. domain 结构规范化；
4. 扩展能力建设；
5. 研究性模块。

研究功能不作为当前主线。

---

# 七、总结

本规划文件的目标是：

- 提供清晰方向；
- 支持自主选择；
- 明确终态目标；
- 保证 system 结构稳定。

EGM 是长期平台型项目。

短期参与者的贡献，应在不改变 system 主轴的前提下完成。
