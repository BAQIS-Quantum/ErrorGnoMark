# ErrorGnoMark Git 开发与分支管理规范

本项目采用单仓库 + 主干集成（Trunk-Based Development + Feature Branch）开发策略。所有开发活动必须严格遵循本规范，以确保架构稳定、历史清晰、协作可控、版本可追溯。

## 分支结构

```
main        → 稳定发布版本（仅用于发布）
develop     → 唯一集成主线
feature/*   → 功能或架构开发分支
```

## 一、分支说明

### main

- 仅用于稳定版本发布  
- 不允许日常开发  
- 只能从 develop 合并  
- 可用于打 tag 和版本归档  

### develop

- 唯一长期集成主线  
- 所有 feature 分支必须合并到此分支  
- 由项目负责人维护  
- 不建议直接 push，推荐通过 Pull Request 合并  

### feature/*

- 每个新任务必须创建独立的 feature 分支  
- 分支名称必须表达功能语义  
- 禁止使用人名作为长期分支名称  

示例：

```
feature/domain-layer
feature/suites-compiler
feature/collab-integration
feature/execution-refactor
```

## 二、标准开发流程

### 1. 开始一个新任务

所有开发必须从 develop 创建新的 feature 分支：

```bash
git switch develop
git pull
git switch -c feature/<short-description>
```

示例：

```bash
git switch -c feature/execution-refactor
```

禁止直接在 develop 或 main 上开发。

### 2. 开发完成后提交代码

```bash
git add .
git commit -m "feat: short description"
git push -u origin feature/<short-description>
```

示例：

```bash
git commit -m "feat: unify benchmark execution interface"
```

### Commit Message 规范

推荐使用以下前缀：

- feat: 新功能  
- fix: 修复问题  
- refactor: 结构重构  
- docs: 文档更新  
- test: 测试相关  
- chore: 构建或杂项  

示例：

```
feat: add domain abstraction layer
refactor: decouple execution from experiments
fix: correct rb fitting instability
```

### 3. 提交 Pull Request

在 Gitee 上发起：

```
feature/* → develop
```

合并前必须满足以下条件：

- 代码可以正常运行  
- 无明显架构冲突  
- 完成基本测试  
- 经负责人审查  

禁止直接 push develop 或未经 review 合并代码。

### 4. 发布流程（develop → main）

当 develop 分支达到稳定状态时，由负责人执行：

```bash
git switch main
git pull
git merge develop
git push
```

发布后可打 Tag：

```bash
git tag v3.0.0
git push origin v3.0.0
```

main 仅用于稳定版本发布与归档。

## 三、分支权限原则

- main：不允许直接 push，仅用于发布  
- develop：仅负责人维护  
- feature/*：允许开发者在各自分支上开发  

## 四、同步主线方法

为避免长期偏离 develop，feature 分支应定期同步：

```bash
git switch feature/xxx
git fetch origin
git rebase origin/develop
```

保持线性历史，减少冲突。

## 五、工程纪律

- 不允许使用人名作为长期分支  
- 不允许直接在 main 上开发  
- 不允许无 PR 合并代码  
- 每个 feature 分支应小而专注  
- 长期未合并分支应及时清理  
- develop 是唯一真实时间线  
- main 是稳定发布快照  

## 六、完整流程示例

```bash
# 开始新功能
git switch develop
git pull
git switch -c feature/new-module

# 开发完成
git add .
git commit -m "feat: implement new module"
git push -u origin feature/new-module

# 提交 PR → 合并到 develop

# 发布版本
git switch main
git merge develop
git push
git tag v3.0.0
git push origin v3.0.0
```

develop 是唯一主线。  
feature 分支是临时工作空间。  
main 是稳定发布快照。  

保持分支清晰，架构才能长期健康。
